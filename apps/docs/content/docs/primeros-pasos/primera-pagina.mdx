La portada del playground usa los mismos exports públicos que esta receta. Primero monta una
página estática; añade movimiento en una frontera cliente pequeña cuando aporte información.

## 1. Instalar y cargar los estilos

```bash
pnpm add @betterlibs/react @betterlibs/tokens @betterlibs/icons
# Solo para movimiento:
pnpm add @betterlibs/motion motion
```

Carga las fuentes en la aplicación, con archivos locales o el paquete de tu elección:

```tsx
import '@fontsource-variable/inter'
import '@fontsource-variable/space-grotesk'
import '@betterlibs/tokens/index.css'
import '@betterlibs/tokens/editorial.css'
import '@betterlibs/react/styles.css'
```

Los paquetes de fuentes son opcionales y deben instalarse si usas estos imports. La librería
no descarga fuentes. Consulta la instalación para [Vite](./vite) o [Next](./nextjs).

## 2. Componer la página

Este componente puede renderizarse en el servidor. FeatureShowcase concentra la selección
cliente; sus contenidos pueden llegar del servidor como nodos React. No necesitas Motion
para mostrar la página ni para manejar sus controles.

```tsx
import { BentoFeature, BentoFeatures, Button, Card, CTA, FeatureShowcase, Hero } from '@betterlibs/react'

export function Page() {
  return (
    <main data-preset="editorial">
      <Hero id="inicio" variant="editorial"
        title="Una interfaz con voz propia"
        description="Contenido claro, controles legibles y espacio para leer."
        media={<Card><h2>Tu próxima colección</h2><p>Contenido de tu producto.</p></Card>}
        actions={<Button asChild><a href="#ejemplos">Explorar ejemplos</a></Button>}
      />
      <BentoFeatures id="ventajas" title="Cuatro formas de crear">
        <BentoFeature title="Identidad" tone="brand" description="Tipografía que organiza." />
        <BentoFeature title="Ritmo" description="Cada gesto tiene una razón." />
        <BentoFeature title="Interacción" description="Foco visible y estados claros." />
        <BentoFeature title="Composición" description="De piezas a páginas." />
      </BentoFeatures>
      <FeatureShowcase id="ejemplos" title="Elige tu siguiente paso" selectorLabel="Ejemplos"
        items={[
          { value: 'leer', label: 'Leer', content: <Card><p>Tu historia, con espacio para leer.</p></Card> },
          { value: 'crear', label: 'Crear', content: <Card><a href="/crear">Crear una colección</a></Card> },
        ]}
      />
      <CTA id="empezar" panelTone="inverse" title="Dale forma a tu próxima idea"
        actions={<Button asChild><a href="/crear">Crear colección</a></Button>} />
    </main>
  )
}
```

Hay un único h1; las secciones usan h2 y sus tarjetas h3. Los IDs nombran las regiones y sirven
para anclas. En imágenes propias aporta alt y dimensiones. El contenido y las acciones son
configurables: usa enlaces para navegar y botones para ejecutar acciones.

## 3. Añadir una frontera de movimiento

```tsx
'use client'
import { AnimatedNumber, MotionProvider, Reveal, Stagger } from '@betterlibs/motion'
import { BentoFeature, BentoFeatures } from '@betterlibs/react'

export function AnimatedFeatures() {
  return (
    <MotionProvider mode="system">
      <div data-motion="system">
        <BentoFeatures title="Una página con ritmo">
          <Stagger>
            <Reveal><BentoFeature title="Tu colección"
              media={<AnimatedNumber value={8} startValue={0} />} /></Reveal>
            <Reveal><BentoFeature title="Tu contenido" description="Siempre visible en SSR." /></Reveal>
          </Stagger>
        </BentoFeatures>
      </div>
    </MotionProvider>
  )
}
```

Reveal no oculta el HTML inicial. AnimatedNumber expone el final a lectores de pantalla, sin
anunciar cada fotograma. Para detalles condicionales, Presence conserva una salida inerte y
puede restaurar el foco con returnFocusRef. Consulta la [guía de movimiento](/docs/guias/movimiento-opcional)
para sus límites; no sustituye un Dialog ni administra el router.

## 4. Revisar estados

Prueba tema claro/oscuro, móvil, texto al 200 %, teclado y tacto. Cambiar a reduced/off cancela
los efectos y muestra el final; la preferencia del sistema siempre prevalece. Aplica la misma
selección a MotionProvider y data-motion, también en los portales.

En Storybook, **Bloques → Editorial → Primera página** permite comparar las composiciones y las
cifras. La portada del playground combina la receta con guardar una colección, probar botones,
editar un formulario y navegar a la plantilla corporativa. El menú y el router conservan título,
foco, historial y scroll. Las transiciones entre rutas no se incorporan en esta fase.

La [referencia de composiciones](/docs/bloques/editoriales) describe los contratos y las opciones.
