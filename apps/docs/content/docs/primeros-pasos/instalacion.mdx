## Estado de distribución

Esta edición se prueba desde el monorepo y paquetes locales. El registro público devolvió E404
para @betterlibs/react y @betterlibs/motion el 13 de octubre de 2026. La publicación en npm está
pendiente; los comandos de esta página no dependen de que ya exista una versión pública.

## 1. Probar el proyecto

Desde la raíz del checkout, con Docker Engine/Desktop y Compose:

```bash
./docker.sh
```

Web: http://localhost:8080; docs: http://localhost:3000/docs; Storybook: http://localhost:6006.
No necesita Node ni pnpm en el host. El script puede pedir sudo en tu terminal si el socket lo
requiere. Cambios en dependencias/configuración requieren volver a construir; las fuentes se recargan.

Para desarrollo sin Docker, el entorno verificado usa Node 24 y pnpm 12.4.1 (packageManager del repo):

```bash
pnpm install --frozen-lockfile
pnpm exec turbo run build --filter='./packages/*'
pnpm --filter @betterlibs/playground dev
```

Abre el puerto que imprime Vite. Cada aplicación se ejecuta desde su workspace; los exports de los
paquetes apuntan a dist, por eso se construyen antes. Para docs usa pnpm --filter @betterlibs/docs dev.
Si usas Vite en 5173, configura NEXT_PUBLIC_PLAYGROUND_URL=http://localhost:5173 en
apps/docs/.env.local para los enlaces de las plantillas. La documentación usa 8080 por defecto,
el puerto del entorno Docker; NEXT_PUBLIC_STORYBOOK_URL configura el enlace a Storybook.

## 2. Consumir desde otra aplicación

Construye los paquetes y empaquétalos, desde este checkout. Usa una carpeta absoluta de tu equipo:

```bash
pnpm exec turbo run build --filter='./packages/*'
pnpm -r --filter './packages/*' pack --pack-destination /ruta/absoluta/paquetes
```

Los tarballs incluyen dist y sus manifiestos de publicación; pnpm transforma los enlaces workspace.
En pnpm 12, un consumidor de tarballs aún no publicados necesita resolver también las dependencias
internas a esos archivos: declara overrides en su propio pnpm-workspace.yaml. La preparación
reproducible `pnpm prepare:release` crea candidatos rc, changelogs y un consumidor aislado que
comprueba esta instalación; conserva las versiones del checkout. El manifiesto de la ejecución
está en docs/quality/release-candidate.json y los archivos en la carpeta .release indicada.

```yaml
packages: []
overrides:
  '@betterlibs/tokens': 'file:/ruta/absoluta/paquetes/betterlibs-tokens-0.0.0.tgz'
  '@betterlibs/icons': 'file:/ruta/absoluta/paquetes/betterlibs-icons-0.0.0.tgz'
  '@betterlibs/react': 'file:/ruta/absoluta/paquetes/betterlibs-react-0.0.0.tgz'
  '@betterlibs/motion': 'file:/ruta/absoluta/paquetes/betterlibs-motion-0.0.0.tgz'
```

Sustituye rutas y versiones por los archivos empaquetados; omite motion si solo consumes UI.
Los overrides se configuran en [pnpm-workspace.yaml](https://pnpm.io/settings), no en el campo
pnpm de package.json. Cuando las versiones estén publicadas, la resolución normal del registro
reemplazará este paso de instalación local.

En una aplicación React 19 que ya tenga React DOM, añade tokens, iconos y UI en la misma operación.
La versión local actual es 0.0.0; sustituye nombres si tu checkout tiene otra versión:

```bash
pnpm add /ruta/absoluta/paquetes/betterlibs-tokens-0.0.0.tgz /ruta/absoluta/paquetes/betterlibs-icons-0.0.0.tgz /ruta/absoluta/paquetes/betterlibs-react-0.0.0.tgz
```

Iconos es una dependencia interna de la UI. No necesitas importar sus exports en tu aplicación
si prefieres otra librería con tamaño 1em y currentColor. Tokens, React y React DOM son peers.
Tu bundler debe entender imports de CSS.

## 3. Estilos y primer componente

Carga una vez en main.tsx o el layout raíz:

```tsx
import '@betterlibs/tokens/index.css'
import '@betterlibs/react/styles.css'
```

Para la dirección editorial, añade el CSS optativo y el atributo:

```tsx
import '@betterlibs/tokens/editorial.css'
import { Button, Hero } from '@betterlibs/react'

export function Page() {
  return <main data-preset="editorial">
    <Hero id="inicio" variant="editorial" title="Una página con identidad"
      description="Contenido claro y acciones que se entienden."
      actions={<Button asChild><a href="#contenido">Explorar</a></Button>} />
    <section id="contenido"><h2>Tu siguiente idea</h2><p>Contenido de tu proyecto.</p></section>
  </main>
}
```

El atributo aplica el preset; cargar su CSS no lo activa por sí solo. Las fuentes las carga tu app.
Si usas los imports de las recetas, instala @fontsource-variable/inter y @fontsource-variable/space-grotesk.
Todo el CSS de la UI está en capas bl.tokens, bl.reset, bl.base y bl.components; las reglas sin
capa tienen prioridad. [Personalización](/docs/guias/sobrescribir-estilos).

## Catálogo avanzado opcional

Para selectores con búsqueda, tablas, calendario y el resto del catálogo avanzado, añade
su entrada y CSS optativos. Los estilos básicos anteriores siguen siendo necesarios:

```tsx
import '@betterlibs/react/advanced/styles.css'
import { Combobox, DataTable, DatePicker } from '@betterlibs/react/advanced'
```

Consulta [componentes avanzados](/docs/componentes/avanzados) para contratos, estados y demos.
Esta entrada reutiliza la UI básica y no añade un motor de arrastre.

## 4. Movimiento, solo si lo necesitas

Añade el tarball de movimiento junto a Motion 14.1 compatible. Tokens debe estar instalado:

```bash
pnpm add /ruta/absoluta/paquetes/betterlibs-motion-0.0.0.tgz 'motion@^14.1.0'
```

El paquete opcional no añade CSS ni cambia las dependencias de la UI estática. Crea una frontera
cliente para sus controles y configura MotionProvider/data-motion de forma coherente.
[Referencia](/docs/movimiento) y [SSR/preferencias](/docs/guias/ssr-y-preferencias).
